# Chapter 11 – Proxy Pattern

**Intent:** provide a surrogate or placeholder for another object to control access to it. The proxy implements the same interface as the real subject, so clients cannot tell them apart.

**Design principles from the chapter**
- Use the proxy to control access: remote (RMI), virtual (expensive creation), protection (access rights).
- Program to an interface, not an implementation. This is why the proxy can stand in for the real subject.
- Keep the proxy's job to access control; the real subject keeps the business logic.
- Related patterns: Decorator adds behavior, Adapter changes the interface, Proxy controls access. All three use composition.

## Structure

```
Client ──▶ Subject (interface) ◀── RealSubject
                 ▲
                 └────────────── Proxy ──has-a──▶ RealSubject

Remote:     GumballMonitor ──▶ GumballMachineRemote ◀── stub (proxy) ──▶ GumballMachine
Virtual:    ImageComponent ──▶ Icon ◀── ImageProxy ──creates lazily──▶ ImageIcon
Protection: client ──▶ Person ◀── dynamic proxy ──▶ InvocationHandler (Owner / NonOwner) ──▶ PersonImpl
```

## Simulation deviations

- **RMI (remote proxy).** No network or `rmiregistry`. `rmi.py` / `Rmi.h` provide `Remote`, `RemoteException` and an in-process `Naming` registry. `Naming.lookup` returns a `GumballMachineStub`, a real proxy object that forwards `getCount/getLocation/getState` to the bound machine. `GumballMonitor` talks only to the `GumballMachineRemote` interface. Because the registry lives in one process, `GumballMonitorTestDrive` first binds demo machines itself (santafe 112, boulder 0, seattle 1). In Java they come from separately started `GumballMachineTestDrive` JVMs. `GumballMachineTestDrive` keeps the usage message and exit code 1 when run without arguments. In C++ the remote `getState()` returns the state's description as a `std::string` (a by-value snapshot, like a serialized State).
- **Randomness.** `HasQuarterState` seeds with `currentTimeMillis()` in Java. Here it uses a fixed seed (Python `Random(42)`, C++ `mt19937{42}`), so the two ports are not bit-identical to each other on winner draws. The sample drives never turn the crank, so output is unaffected.
- **`GumballMonitor.toString`.** Java prints `GumballMonitor@<identity hash>`. Ports print `GumballMonitor@1`, `@2`, `@3`.
- **Virtual proxy.** No Swing, threads, or network. `swing_sim` / `SwingSim.h` supply console `Graphics`, `Component`, `Icon` and a fake `ImageIcon` (fixed 300x300, constructing it stands in for the download). Java's retrieval `Thread` becomes a `SimulatedThread` run by a `Scheduler`: the "download" finishes after 2 `tick()` calls, then the proxy calls `repaint()`. The menu is replaced by explicit `menuItemClicked(name)` calls from `main`. Album order is insertion order (Java's `Hashtable` order is hash-based). There is no Java output to diff for this program; Python and C++ agree with each other.
- **Dynamic proxy.** See the table below.

## Java vs Python vs C++ in this chapter

| Topic | Java | Python | C++ |
|-------|------|--------|-----|
| Dynamic proxy | `Proxy.newProxyInstance(loader, interfaces, handler)` generates a class at runtime via reflection | `__getattr__` returns a closure per method name that calls `handler.invoke(proxy, name, args)` | No runtime reflection, so no generated classes. A hand-written `PersonProxy` implements `Person` and forwards every call to an `InvocationHandler::invoke(methodName, args)`. A hand-written `invokeOn()` replaces `Method.invoke`. One proxy class per interface must be written by hand (or generated by a tool/macros) |
| Method/args representation | `Method`, `Object[]` | name string, tuple | name string, `std::vector<std::variant<monostate,int,string>>` |
| Access denied | `IllegalAccessException` (wrapped in `UndeclaredThrowableException` at the proxy) | custom exception class | `IllegalAccessException : std::runtime_error`; callers `catch (const std::exception&)` |
| Interfaces | `interface Person`, `Icon`, `State` | `abc.ABC` | classes with pure virtuals and virtual destructors |
| Remote proxy | RMI stub generated by the runtime, `RemoteException` checked | explicit `GumballMachineStub` | explicit `GumballMachineStub` in `GumballMachineRemote.h`, held by `shared_ptr` |
| Ownership | GC | GC | `GumballMachine` owns its `State`s with `unique_ptr`; states keep a raw back-pointer (like Java's `transient` field), so there is no cycle. Handlers share the target `Person` via `shared_ptr` |
| Lazy loading + callback | thread captures `c` and `this` | closure captures them | lambda captures a `weak_ptr` to the proxy, so a replaced `ImageProxy` is not kept alive by a pending load |
| Serialization of State | `Serializable`, `transient` | n/a | n/a (snapshot string) |
